What is RAG?

Retrieval-Augmented Generation

An AI architecture that retrieves relevant documents from a knowledge base and injects them as context for an LLM to generate grounded answers.

The LLM answers using your data — not just its training data.

Analogy

Open-book exam vs. closed-book exam:

  • LLM alone → closed-book (relies on memory, may hallucinate)
  • LLM + RAG → open-book (looks up facts, cites sources)

Embeddings — The Bridge Between Text and Math

What is an Embedding?

A dense vector (list of floats) that captures the semantic meaning of text.

"vector database" → [0.023, -0.451, 0.789, ...]  (1024 values)

Similar texts → similar vectors (nearby in vector space).

BGE-M3 by BAAI

  • 1024 dimensions
  • 100+ languages
  • MIT license
  • Runs on CPU via Ollama
  • Supports dense, sparse, and multi-vector retrieval

How Embeddings Enable Search

"cheap hotel in Paris"
↕ cosine similarity
≈
"affordable accommodation near Eiffel Tower"
(no keyword overlap!)

pgvector — Vector Search in PostgreSQL

Distance Operators

OperatorMetricRangeUse Case
<=> Cosine distance [0, 2] Text / semantic search
<-> L2 (Euclidean) [0, ∞) Images, magnitudes matter
<#> Negative inner product (-∞, ∞) Dot-product-trained models

We use <=> — cosine similarity ignores magnitude, which is ideal for text.

Index Types

IndexBuildQueryMemory
IVFFlatFastModerateLow
HNSWSlowFastHigher

IVFFlat: lists = sqrt(n), searches nearest probes clusters.

HNSW: Hierarchical graph. Parameters m (links) and ef_construction.

Why pgvector?

  • No separate vector DB — vectors live alongside relational data
  • Transactional consistency (ACID)
  • Backup with pg_dump
  • Combine vector search with SQL filters: WHERE category = 'hotel' ORDER BY embedding <=> $1
  • Mature, active open-source project

Technology Stack

🛢️ Storage

PostgreSQL 16 + pgvector

Relational data + vector index in one database. ACID compliant, familiar tooling.

🧠 Embeddings

Ollama + BGE-M3

Local model server. 1024-dim dense vectors. MIT license. Runs on CPU.

🤖 Chat Model

OpenRouter → gpt-oss-120b

Single API key, dozens of models. Free tier available. Falls back to Ollama local.

⚙️ Backend

Go 1.26

Fast startup, great concurrency, single binary. Standard library + chi router.

🎨 Frontend

Vanilla JS + CSS

Minimal chat UI. No framework dependency. Session ID stored in localStorage.

🐳 Deployment

Docker Compose

PostgreSQL + Ollama in containers. Backend runs natively (avoids corporate TLS issues).

Use Case: Travel Agency AI Assistant

Scenario

A travel agent needs to prepare a 10-day Japan family trip for the Smith family (2 adults, 2 kids under 10). The knowledge base has destination guides, hotel catalogues, flight schedules, visa rules, and client profiles.

Indexed Data

-- Destinations (attractions, hotels, restaurants)
CREATE TABLE destinations (
  city TEXT, category TEXT,     -- 'hotel', 'attraction', 'restaurant'
  title TEXT, content TEXT,
  metadata JSONB,               -- price, rating, season
  embedding VECTOR(1024)
);

-- Client profiles with preferences
CREATE TABLE client_profiles (
  name TEXT, preferences JSONB, -- diet, budget, activity level
  passport_data JSONB,
  embedding VECTOR(1024)
);

Beyond the Demo — Production Enhancements

🔍 Hybrid Search

Combine vector search (<=>) with keyword search (PostgreSQL tsvector / ts_rank):

WHERE embedding <=> $1 < 0.5
   OR ts_content @@ to_tsquery('english', $2)
ORDER BY ts_rank(ts_content, to_tsquery($2)) DESC;

Catches exact matches + semantic matches.

🔄 Re-ranking

Retrieve top 20 with pgvector, then re-rank with a cross-encoder (e.g., BGE-reranker).

1. pgvector: TOP 20 (fast, approximate)
2. Cross-encoder: score each (100ms each)
3. Return TOP 5 (high precision)

Improves precision significantly at minimal latency cost.

🏷️ Metadata Filtering

WHERE metadata->>'category' = 'hotel'
  AND (metadata->>'price')::int < 200
ORDER BY embedding <=> $1
LIMIT 5;

Hybrid queries — vector search within a filtered subset.

📊 Evaluation & Monitoring

  • Hit rate: % of queries where user clicked a source
  • Precision@k: relevance of top-k results
  • Latency: embedding + search + generation time
  • A/B test different embedding models, chunk sizes, retrieval counts
